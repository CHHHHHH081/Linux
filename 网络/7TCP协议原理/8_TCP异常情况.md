# 一、TCP异常情况

## 1. 异常连接

1. **进程终止**：进程终止会自动释放文件描述符，通信双方**正常四次挥手结束通信**。
2. **机器重启**：与进程中止情况相同。关机之前，系统会关闭所有进程。
3. **机器掉电或网线断开**：接收端在未发生读写时会认为连接依然存。一旦接收端进行写入操作，就会发现连接已经不存在，**进而触发 Reset（RST）报文重置连接**。即便没有写入操作，**TCP 内部也内置了保活定时器，会定期询问对方是否在线，即发送一条没有数据的TCP报文**，若对方长期无响应也会自动释放连接。
4. **应用层检测机制**：除了传输层自身的保活机制外，应用层协议也会设计类似的检测机制（例如 HTTP 长连接中的心跳检测）。像 QQ 等应用在断线后，也会在应用层尝试重新连接。

**因此TCP对于异常连接有很强的容错处理。**

## 2. TCP保活机制（keepalive）

为了应对无数据传输场景下的静默断网问题，TCP 提供了 Keepalive 保活机制：

1. TCP 内置保活机制的时间间隔通常较大（通常是大约几十分钟级别）。
2. 在实际开发中，更及时有效的保活机制往往是由应用层自行实现的（如应用层心跳包）。
3. 保活报文主要用于探测连接连通性，通常不包含有效数据载荷。
