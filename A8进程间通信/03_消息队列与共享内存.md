# A8｜消息队列与共享内存

## 1. 消息队列

消息队列以离散消息为单位保存数据，发送方使用 `msgsnd`，接收方使用 `msgrcv`，可按类型选择消息。它天然保留消息边界，适合传递命令、事件和任务描述。

System V 常见流程：`msgget` 创建/获取队列 → `msgsnd/msgrcv` 收发 → `msgctl(..., IPC_RMID, ...)` 删除。创建者应记录队列 ID，并在异常退出时清理；可用 `ipcs -q`、`ipcrm -q <id>` 检查和删除对象。队列满时发送可能阻塞，非阻塞模式需处理 `EAGAIN`。

## 2. 共享内存

共享内存把同一物理页映射到多个进程，是大块数据交换效率最高的 IPC 方式之一。System V 流程：

```text
ftok → shmget → shmat → 读写 → shmdt → shmctl(IPC_RMID)
```

共享内存只负责“共享”，不负责“谁先写、谁后读”。必须配合信号量、进程共享互斥锁、条件变量或原子变量建立协议。例如生产者先写入数据，再更新长度并释放“可读”信号；消费者读取完成后再释放“可写”信号。

## 3. 内存可见性与一致性

多个进程同时访问共享结构体时，即使单次读写看似简单，也可能发生竞态。同步原语不仅提供互斥，还要建立内存可见性顺序。环形缓冲区通常需要读位置、写位置、容量和两个计数信号量，并约定初始化、关闭和错误恢复规则。

## 4. 资源清理

`shmdt` 只表示当前进程解除映射；`IPC_RMID` 才是标记内核对象删除。程序崩溃后遗留的消息队列、共享内存和信号量会持续占用内核资源，应使用 `ipcs` 定期检查。共享内存中不要保存进程私有指针，应保存偏移量或固定布局数据。
